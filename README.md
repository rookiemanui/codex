# 本地账本 · 小店收支与库存

一个由电脑保存数据、电脑和安卓浏览器共用的本地记账软件，当前为 **0.3.2 餐饮测试版**。
支持截图审核、收支分类、分日/月汇总、退款、内部转账、原料库存、菜品配方、收银订单、销售小票打印/PDF和逐笔备份。

按餐饮店共用一本账设计，电脑必须保持运行。局域网可直接使用；外网提供带独立密码的 HTTPS 试用入口，见下文。
财务数据与图片不需要发送到云端 AI；基本记账无需购买接口或订阅。
首次安装可选 OCR 组件需要下载免费依赖和官方模型，准备后可本地识别。

本版新增每日总额核对、购物车与收银中断恢复，并优化月账本查询。开发工具与技能见 [工具与优化](docs/工具与优化.md)。

Chrome网页版可双击 `用Chrome打开账本.bat` 启动，详见 [Chrome使用说明](docs/Chrome网页版.md)。

## 先运行本地测试版

完整解压软件，安装Python 3.12和Chrome后，双击 **`启动测试版.bat`**。
程序会运行本地服务、打开浏览器；输入启动窗口显示的连接码即可操作。
模拟账本独立存放在 `test-data`，带测试标识，关闭程序后保留，下次继续使用。
已有正式目录不能用测试模式打开。详见 [本地测试版说明](docs/本地测试版.md)。
当前测试交付使用带后端的程序；历史单文件演示不再作为试用入口。
交互问题与工具精简建议见 [交互与工具检查](docs/交互与工具检查.md)。

## Windows 使用

1. 将软件完整解压到自己选择的位置，例如 `D:\本地账本`。
2. 安装 **Python 3.12（64位）**。首次安装 Python 可使用 python.org 官方安装程序。
3. 双击 `启动账本.bat`，浏览器会打开软件。
4. 输入启动窗口显示的六位连接码。每次重启更换连接码。
5. 要启用自动截图识别，关闭程序后运行 `安装截图识别.bat`；首次需要下载约百余 MB 模型及 Python 依赖。

默认账本保存在软件旁边的 `data` 文件夹。整个软件解压到 D 盘，账目和图片也会留在这个位置。
更换数据目录可以从命令行启动：

```powershell
py -3.12 run.py --data-dir "D:\店铺数据"
```

安装 OCR 时使用相同数据目录：

```powershell
.\安装截图识别.bat --data-dir "D:\店铺数据"
```

当前交付包含源码、Windows 启动和安装脚本；未在 Windows 真机运行或签名，也未提供已验证的 Windows EXE。
核心程序已在 Linux + Chromium 的桌面与手机尺寸下验证。

## 安卓手机连接

1. 手机和电脑连接相同 Wi-Fi。
2. 电脑启动窗口会列出可用的局域网地址。手机浏览器输入对应地址和相同连接码。
3. 若 Windows 防火墙询问，按自己的局域网需求允许程序在**专用网络**通信。
4. 可在安卓浏览器中将地址添加到主屏幕，方便下次打开。

电脑关闭、休眠或断网后，外面也无法访问。软件不提供多台主机间的云同步或员工权限分级。

### 手机在外面访问

没有服务器或域名时，可按 [外网试用说明](docs/外网与支付接入.md) 准备官方 cloudflared，运行 `启动外网试用.bat`。
首次设置独立密码，之后手机与电脑均使用窗口中的 HTTPS 地址。临时入口可能换地址、没有在线保证，且会经过第三方隧道服务。
当前云环境无法连接该隧道服务，尚未完成真实公网与 Windows/安卓真机验收；不能承诺在你的网络一定连通。
连接码持有人可操作整本账，因此适用于本人或可信的小店成员共用。

## macOS / Linux 或开发运行

```bash
python3 run.py
# 仅让本机访问：
python3 run.py --host 127.0.0.1
```

核心服务只使用 Python 标准库，无需 npm、数据库服务器或在线账号。
可选截图识别环境：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements-ocr.lock
.venv/bin/python scripts/prepare_ocr.py
.venv/bin/python run.py
```

OCR 文件来源和锁定哈希见 `scripts/ocr-models.json`。首次下载建立在已验证的官方 HTTPS 来源之上，
哈希用于锁定本版文件，不是发行方额外提供的签名。不要关闭 TLS 或哈希校验来解决下载错误。

## 使用流程

- **截图记账**：批量选择 PNG、JPG 或 WebP，每张最多20MB。先保存原图及其副本，再进行本地识别。
  一张图允许多笔交易。用户核对金额、时间、账户、用途和类别后，逐笔确认入账。
  中断退出后，重新启动会接着处理尚未完成的图片；已确认入账的条目不会重复新增。
- **每日核对**：在总览选择日期和账户，填写当天净收入或净支出总额。只核对差额，不再次记账；退款和之后的账目修改会重新计算差额。
- **日常收支**：手动记录销售总收款、采购支出等。没有商品明细时，填写实际用途。
- **分类学习**：勾选记住具体用途关键词，例如“猪肚鸡调料”。不把“淘宝”“抖音”等平台一律归为某类。
- **退款**：必须关联原支出。退款冲减原类目净支出，不作为营业收入；支持多次部分退款且不能超额。
- **转账**：银行卡到零钱、自有账户信用卡还款等选择“转账”，不重复计为消费。
- **库存**：新建商品或原料，指定件、瓶、袋、千克等单位。支持入库、出库、领用、损耗、退货、盘点与补货线。
  数量最多三位小数。只有实际提供数量后才变动库存，不会凭一笔金额推测数量。
- **关联收支**：入库或出库时可以同时新增一笔采购支出或销售收入。两者同时成功或同时失败。
  已记过的收支请勿再次勾选新增。保质期批次或自动成本核算尚未提供。
- **餐饮菜品与收银**：先在库存中建原料并入库，再在“餐饮收银 → 菜品与配方”填写菜品、唯一编码、售价和每份用量。
  用量必须采用原料库存单位：单位为千克时500克填0.5。也可明确选择手工领料，避免重复扣库。
  点选菜品或用键盘式扫码枪扫描**菜品编码**加单；当前尚不支持扫描顾客付款码发起扣款。
  通过店铺现有方式收款后，核实实收、账户与流水号，再保存销售。销售收入、订单明细、配方领料同时成功或同时失败。
  价格变化、原料不足、相同收款流水号等会报备，不会默默只保存一半。
  浏览器保留本机购物车；请求结果不明时先“核实上次收银结果”，沿用原编号，避免重开单。
  清除浏览器数据、更换设备或临时域名后不能依赖这份草稿，请先核对最近销售小票；不要在多个标签同时处理同一单。无配方的菜品须另行领料。
- **销售小票**：查看已保存小票，支持58/80毫米打印布局，浏览器打印对话框可选“另存为PDF”。
  先在设置里填写店名、地址和电话。小票不是税务发票；实际打印机兼容性需按型号验证。
- **销售退单**：在销售小票页办理整单退款，先实际退还款项再人工确认。退单冲减销售收入，不记为采购支出。
  保留原小票和退款记录，不自动将已烹饪原料回库；本版暂不支持部分退菜。
- **避免重复营业收入**：已经通过销售订单入账的收入，不要再把当日收款总额新增成一笔收入。日总额用于核对。
- **手机共用**：总览、账目和库存页在未编辑时每10秒更新，电脑与手机连接同一数据库。

金额以整数“分”存储；数量以整数千分单位存储。同金额、同秒的不同交易均会保留。
原图按文件哈希识别重复上传；有明确交易编号的同平台同类型交易会提示重复。
截图缺少日期、用途、账户时须核对，不会假装已经识别完整。

“收支结余”是收入减净支出，不是经营利润；采购库存金额也不是已售商品成本。
第一版不计算税务报表、毛利或真实银行余额。

## 每笔备份与恢复

`data/ledger.sqlite3` 是主账本；`data/receipts` 保存实际上传的原图。

- 原图上传后另存一份到 `data/backups/receipts`。
- 每次账目、分类、库存等变更都写入数据库事件，并独立生成 JSON 到 `data/backups/records`。
- 每次变更更新当日一致性数据库快照。中断后可从数据库事件补齐缺失或损坏的逐笔 JSON。
- “备份与设置 → 下载完整备份”包含一致性数据库、原图、逐笔事件及已有历史导入出处。
- 若备份失败会明确提示“账目已保存，但独立备份未完成”，不要再次录入同一笔，应先检查磁盘空间并重试备份。

恢复方法：关闭软件，把备份 ZIP 解压到**新的空文件夹**，例如 `D:\账本恢复`，然后运行：

```powershell
py -3.12 run.py --data-dir "D:\账本恢复"
```

备份解压后应直接看到 `ledger.sqlite3` 和 `receipts` 等文件。不要用不同格式的旧账本数据库替换本软件数据库。
同盘副本不能防止整块磁盘损坏，建议定期将下载包另存到其他磁盘。

## 已有账目迁移

`scripts/import_legacy.py` 可以只读迁移之前使用的 Bookkeeping 工具中已确认的收入和支出。
不会改动原账本，不会为旧记录虚构原图，也不会直接覆盖新账本。

```powershell
py -3.12 scripts\import_legacy.py "D:\旧账本\bookkeeping.db" --data-dir "D:\店铺数据"
```

同一来源路径的重复导入不会重复新增。尚未确认或包含其他交易类型的旧账本会拒绝导入，避免错误转换。
已有账目存于忽略的 `data` 目录，**不包含在Git仓库或通用软件分发包中**。

本地EXE/桌面窗口工具已在云工作区准备，版本、验证结果及Windows限制见 [本地打包工具](docs/本地打包工具.md)。
