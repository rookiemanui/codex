# 外网与扫码扣款：当前能做什么

目前按你的选择：餐饮店电脑保存账本并保持开机，电脑与安卓共用；需求验证后再迁移。
没有商户付款码接口，因此**当前版本不会扫描顾客付款码发起扣款**。

## 没有服务器、域名或公网 IP 时，如何试外网

软件附带 `启动外网试用.bat`，使用 Cloudflare 的临时隧道。它不要求你先购买服务器或域名，
但不是稳定经营方案：地址可能在重启后改变、没有在线时长保证，所在网络也可能无法连接。
Cloudflare 官方客户端的说明将此方式定位为试验；正式部署应改用预先创建的命名隧道或其他持续运行的部署。
不能据此承诺永久免费、稳定或适用于任何商业规模。

来源核对（2026-10-19）：

- [cloudflared 官方 README 的 TryCloudflare 部分](https://github.com/cloudflare/cloudflared#trycloudflare)
- [客户端中的免责声明与实现](https://github.com/cloudflare/cloudflared/blob/master/cmd/cloudflared/tunnel/quick_tunnel.go)
- [官方服务条款](https://www.cloudflare.com/website-terms/)

### Windows 试用步骤

1. 关闭正在运行的账本启动窗口。先用模拟账本试连接，例如在终端运行：
   `启动外网试用.bat --data-dir "D:\账本外网测试"`。
2. 从 [Cloudflare 官方发布页](https://github.com/cloudflare/cloudflared/releases) 下载适合电脑的 Windows 客户端。
   将官方 `cloudflared-windows-amd64.exe` 放在软件旁边，命名为 `cloudflared.exe`。
   根据自己的 CPU 选版本；不要从不明网盘下载。客户端不包含在本软件分发包中。
3. 双击 `启动外网试用.bat`，首次会让你在电脑终端设置至少12位的独立密码。
   密码不会回显，程序仅保存带随机盐的 PBKDF2 摘要。请不要把密码或商户密钥发到聊天里。
4. 等窗口显示 `https://...trycloudflare.com` 地址。电脑与安卓浏览器均使用该 HTTPS 地址和独立密码。
   外网模式下不使用六位连接码，也不通过本地 HTTP 地址登录。
5. 手机关闭 Wi-Fi，切换移动网络，登录并登记一笔明确标注的测试收入；在电脑同一地址核对是否出现。
   再测试导入图片、打印/PDF和完整备份。模拟数据验证后再决定是否连接实际账本。
6. 关闭窗口会关闭临时入口，数据目录仍保留。电脑关闭或断网时，外面也无法访问。

隧道服务会转发浏览器与账本之间的数据，并处理 HTTPS，因此会引入第三方网络服务。
OCR 仍在账本所在电脑进行。临时地址不是密码，应始终使用独立密码。
在外网模式，程序只监听本机回环接口，校验代理请求的域名和 HTTPS 标记；登录 Cookie 带 Secure、HttpOnly、SameSite，写操作需 CSRF 校验。
本版是同一店主/可信家庭成员共享账本，不具备员工角色、操作员身份区分或正式公网高可用部署能力。

遇到问题：

- 找不到 cloudflared：确认文件位置和文件名，或用 `--cloudflared "D:\工具\cloudflared.exe"`。
- 端口被占用：先关闭其他账本窗口，或加 `--port 8766`。
- 一分钟内拿不到地址：检查网络。可退回本地运行；不要通过关闭密码、TLS 或直接映射六位连接码端口解决。
- 出现 403：确认使用窗口中显示的完整 HTTPS 根地址；反向代理必须保留该 Host，提供 `X-Forwarded-Proto: https`。
- 502/连接失败：确认电脑未休眠、程序与隧道都在运行。暂时无法连通时不要在别处另建账本重新录入相同数据。
- 忘记密码：关闭程序，在数据目录对应的命令中运行 `py -3.12 run.py --data-dir "D:\店铺数据" --set-password`，然后重启。
  密码文件 `access.json` 与具体电脑的数据目录关联，完整账目备份不包含密码；恢复后重新设置即可。

当前云执行环境对 Cloudflare 域名的连接返回代理403，**没有完成真实公网隧道连通验收**。
已验证的是应用的代理域名校验、密码认证、Secure Cookie、CSRF、会话退出，以及临时入口启动器的本地模拟集成。
Windows 与安卓真机、当地网络连接是否可用，需要按上述步骤验收；不能把模拟集成视为外网已经打通。

## 未来稳定入口与迁移

如果日常试用成立，可保留电脑作为数据主机并采用自己控制域名下的命名隧道；或者将整个账本迁到持续运行的服务器。
命名隧道、域名、托管资源的资格与费用以提供商当时规则为准。电脑关机后仍可访问，必须有另一台持续运行的主机。

附有 `deploy/Caddyfile.example`。有域名与相应主机后，可用 Caddy 提供 HTTPS，并运行：

```bash
python run.py --data-dir /path/to/shop-data --set-password
python run.py --data-dir /path/to/shop-data --host 127.0.0.1 --public-url https://ledger.example.com --no-browser
```

先停机、导出完整备份，在新主机恢复后核对笔数和金额，再切换入口。
不要让两台机器同时维护两个独立账本；本版没有多主同步。

## 顾客付款码扣款仍需商户申请

请先通过 [微信支付商户平台](https://pay.weixin.qq.com/) 或 [支付宝开放平台](https://open.alipay.com/)
确认主体资质、结算账户、可用接入方式以及“商户扫描用户付款码”的支付权限。
普通个人收款二维码不等同于这个权限。开通资格、审核、费率和结算规则由平台确定，本软件不承诺零手续费或一定获批。
可以先申请一家通道；是否使用服务商或聚合通道，应核实合同、资质及其费用。

开通后，接入前需要确认这些**非密钥信息**：支付通道、直连/服务商模式、商户应用信息、已获准的接口、测试与上线要求。
证书与密钥应只配置到本机/服务器的受限目录，不放进浏览器、普通账本导出、Git 仓库或聊天记录。

真正的扣款模块必须具备以下行为，不能只做一个扫描输入框就宣布完成：

- 服务器创建唯一支付订单号；同一笔重试沿用同号，不能多次扣款。
- 付款码只用于当次支付，不写入账目、原图备份或常规日志。
- 对“用户支付中”和网络超时保留待查询状态，按平台规则查单/撤销，不能直接判断失败并重新收费。
- 验证平台响应/回调签名并核对商户、订单号、币种与金额；只有服务器确认支付成功才记销售收入和配方领料。
- 处理支付成功但本机异常的恢复，并协调库存不足、支付退款与平台对账。
- 在获准的测试环境或按平台规范，以明确知情的测试交易完成支付、查单、超时、撤销、退款和日终对账验收。

当前程序提供的是**人工核实实收后保存销售**，没有支付SDK、扣款接口或平台支付成功回调，
也不会把它描述成已经实现的自动扫码支付。申请完成后仍需实际开发和验收以上模块。
