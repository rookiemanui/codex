## 已确认的问题与处理

| 问题 | 验证与处理 |
| --- | --- |
| 旧静态演示保存后清空筛选、改菜品数量重置收款方式 | 浏览器复现；本次停止该独立页的交付，改用已有后端界面；本地版另行验证筛选保持和收款方式记录 |
| 完整版切换记账类型丢失已填内容 | 保存共用字段和各类型的类目、转入账户及学习选项，来回切换可恢复 |
| 手动记账出现无法完成的“销售退款”选项 | 去除错误入口，提示从销售小票选择原单办理退单；退款仍保持原有服务器限制 |
| 必填项/金额精度只依赖浏览器弹出校验 | 手动记账增加明确的表单内提示，并定位错误字段；保存金额精度仍由服务器校验 |
| Esc、取消或误点背景直接丢失未保存内容 | 关闭前检查改动，选择继续编辑后保留内容；保存中禁止关闭 |
| 弹窗没有限制键盘焦点和背景操作 | 背景使用inert，Tab在弹窗内循环，关闭时恢复焦点和页面滚动 |
| 搜索延迟回调可能在切页后改写页面、抢走焦点 | 清理定时器，校验当前页、请求次序、查询条件和弹窗状态后再更新 |
| 手动记账请求结果不明时，改类型可能换请求编号造成重复入账 | 保留原请求和完整内容，锁定输入，通过“核实上次保存并备份”重试；在当前弹窗内验证服务端已保存但响应丢失时不会重复入账 |

本地测试模式使用独立目录，首次预填明确标识的模拟收支、库存与菜品；重启保持修改，拒绝打开已有非测试目录。
真实凭证和账本没有用于浏览器测试，测试使用临时目录。

## 工具是否有多余

| 工具或技能 | 结论与建议 |
| --- | --- |
| Python标准库、SQLite、Chrome | 当前本地测试版的必需部分，无需npm、数据库服务器或付费API |
| PaddleOCR/PaddlePaddle与已验证的两项模型 | 截图自动识别时才需要；基础测试可不安装，人工核对仍必需 |
| Playwright CLI与Python Playwright | 两套入口功能重叠：前者用于交互排查，后者用于现有自动回归。均属开发工具，不应随普通安装强制安装；若精简开发环境，可只保留Python回归入口 |
| PyInstaller与Nuitka | 两种替代打包路线，当前源码测试版两者都不依赖；今后做Windows EXE时选一种即可，建议先评估PyInstaller |
| pywebview、Qt、QtWebEngine、patchelf | Chrome模式无运行依赖；独立桌面窗口或Linux打包才用。当前测试路线可停用，后续需要再恢复 |
| 旧 `/workspace/ai-bookkeeping` 中Bookkeeping与PaddleOCR MCP | 新程序直接本地OCR，不经过这些MCP；功能重复，建议归档。旧目录包含真实账本与备份，不能整目录当缓存删除；本会话也未将旧MCP注册为可调用工具 |
| Ruff、pip-audit | 开发检查工具，不属于客户端运行依赖；保留在独立开发环境即可 |
| playwright、restaurant-ledger-maintenance技能 | 本次检查有实际用途，保留 |
| security-best-practices技能、skill-installer安装器 | 备用审查说明与安装辅助，平时不运行；文件很小，不是启动慢的原因 |
| 下载缓存与打包验证产物 | 可再生成，但缓存可能通过硬链接与虚拟环境共享文件，删除后的实际可释放空间不能按目录大小简单相加 |

本次没有继续安装新的运行工具，也没有卸载用户此前明确要求安装的工具。
当前交付只要求Python与Chrome；打包、浏览器回归、代码检查、MCP均不加入普通用户启动流程。

抽查目录：打包环境按文件链接独立计数约576MiB、旧OCR环境约1.2GiB、新OCR环境约1.2GiB，
这些不是可直接相加的磁盘占用；存在共享硬链接。旧模型缓存约1.4GiB，开发缓存约682MiB。
以上仅反映本次云工作区，不代表Windows电脑安装情况或实际可释放容量。
