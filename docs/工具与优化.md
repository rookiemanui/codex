### 在新机器准备开发环境

这部分仅供开发维护，不是普通记账安装要求：

```bash
python -m venv .dev-venv
# Windows把 .dev-venv/bin/python 换成 .dev-venv/Scripts/python.exe
.dev-venv/bin/python -m pip install --require-hashes -r requirements-dev.lock
.dev-venv/bin/ruff check --config ruff.toml localledger run.py scripts tests
python -m unittest discover -s tests -v
npm ci --prefix devtools --ignore-scripts --no-audit --no-fund
```

浏览器CLI在本云机器需要 `XDG_CACHE_HOME=/workspace/tooling/cache`，避免默认缓存写到只读的用户目录。
本次已使用固定版本CLI启动真实Chromium，登录模拟账本并检查每日核对界面。
CLI会启动浏览器守护进程，完成后只关闭本次命名会话，不影响其他任务。
Windows上的浏览器路径与真机安装仍需适配验收，不能复制 `/usr/bin/chromium` 作为Windows路径。

## 软件改进

1. **每日总额核对**：总览点击每日核对，选择日期与账户，填写实际净收入/净支出总额。
   只保存核对值及独立审计备份，不新增收支；退款冲减、内部转账排除。账目之后有变化会重新显示差额。
   两台设备同时改核对值时检查版本，避免覆盖他人修改。净额为负或为0均可核对。
2. **收银中断恢复**：同一浏览器保留购物车；提交前保存完整请求及原编号。
   网络结果不明时保留待核实状态，刷新后点击核实上次收银结果，沿用原请求，返回已保存的小票，避免新增第二单。
   已通过真实HTTP测试模拟“服务端已入账、客户端响应丢失”。草稿保存在当前浏览器，清除浏览器数据或更换临时域名不会自动带过去；
   它不是跨设备购物车同步。若换设备或地址，应先核对销售小票再继续。不要在多个标签同时操作同一单。
3. **账本查询**：合并退款统计，增加退款索引和日期范围查询，最近账目只返回6条，月汇总仍统计全部记录。
   6300条模拟记录中，旧方式6301次查询约1.385秒，新方式1次查询约0.065秒。
   仅为本云机器查询测试，不包含写入备份或OCR，不代表Windows/安卓性能。
4. **数据保留**：已有账目升级前备份，升级后逐字段对比，金额与记录保持一致。
   模拟菜品、销售和基准数据均不写入真实账本。

仍未具备微信/支付宝付款码扣款接口；临时公网隧道未完成真实连通验收；Windows/安卓、打印与扫码设备须现场验证。
这些限制没有因为安装技能而消失。
