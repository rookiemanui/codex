## 重复安装与验证

`requirements-packaging.in` 固定三个工具的版本和平台条件；
`requirements-packaging-linux.lock` 是本次Linux/Python3.12完整解析的依赖及哈希，**不能当作已经验证过的Windows锁文件**。

```bash
uv venv /workspace/tooling/packaging-venv --python python --cache-dir /workspace/tooling/cache
UV_CACHE_DIR=/workspace/tooling/cache uv pip sync requirements-packaging-linux.lock --python /workspace/tooling/packaging-venv/bin/python --require-hashes
NUITKA_CACHE_DIR=/workspace/tooling/cache/nuitka /workspace/tooling/packaging-venv/bin/python scripts/verify_packaging_tools.py
```

Nuitka默认缓存指向只读的用户目录。本次使用其支持的NUITKA_CACHE_DIR参数将缓存保存到工作区，
并对固定版本使用 `--update-check=never`，不需要为版本查询临时访问更新服务。
所有下载仍保留TLS校验；安装锁文件保留包哈希校验。

实际构建和验证产物位于 `/workspace/tooling/validation/packaging`，不在Git仓库中。
PyInstaller和Nuitka测试程序使用独立的内存SQLite，不包含真实账目；这些Linux文件不能当作Windows EXE使用。
pywebview在无显示器环境使用Qt离屏后端测试，存在GPU/D-Bus环境告警；本地HTML/JS验证通过，不代表桌面显示、打印或Windows运行时验收。
离屏测试中针对受限容器使用的Chromium参数仅用于合成网页验证，不作为正式软件默认配置。

## 在Windows上安装这些工具

以下是待在目标Windows设备上执行的步骤，不表示已经替用户执行：

```powershell
py -3.12 -m venv .packaging-venv
.\.packaging-venv\Scripts\python.exe -m pip install -r requirements-packaging.in
.\.packaging-venv\Scripts\python.exe scripts\verify_packaging_tools.py
```

Windows按平台条件安装所需依赖，跳过仅适用于Linux的Qt额外包和patchelf；
仍需确认pywebview所用的WebView2运行时以及Nuitka支持的C编译器。
在Windows解析并记录其依赖锁文件后，才能声称Windows构建环境可重复恢复。

PyInstaller需要在Windows环境构建Windows版。普通记账版与包含PaddleOCR的版本应分别打包验收，
后者还涉及模型、动态库和运行时依赖。当前安装完成的是工具链，不是已经完成账本Windows EXE发布。
