# 0.3.3 本地测试版

这份测试版包含Python服务、SQLite账本和浏览器界面。请完整解压并启动程序，不能只打开其中的HTML。
它是源码测试包，包含Windows启动脚本，不是免安装EXE。当前在Linux与Chromium验收，Windows电脑尚需实机验证。

## Windows操作

1. 将完整压缩包解压到例如 `D:\餐饮账本测试版`，不要在压缩包窗口内直接运行。
2. 安装官方Python 3.12（64位）与Google Chrome。基本收支、库存、收银不需要安装其他工具。
3. 双击 `启动测试版.bat`，保留启动窗口。Chrome自动打开后，输入窗口内的六位连接码。
4. 页面显示“本地测试版 · 模拟账本”。可测试记账、采购入库、配方销售、小票打印和备份。
5. 退出时在启动窗口按Ctrl+C。测试修改保存在同目录的 `test-data`，重启不会重置。

同一Wi-Fi的安卓手机可用启动窗口列出的局域网地址和同一连接码，共用测试账本。
电脑需保持运行；外网需另行验证，见 [外网与支付接入](外网与支付接入.md)。

第一次测试账本含虚构收入120元、支出68.40元、三种原料和三种菜品；所有名称带“测试”标识。
初始收入是手动模拟日收入，没有伪造对应销售小票。自行试收银后才会产生订单与小票。
扫码枪输入菜品编码1001、1002、1003可加单；软件尚未开通扫描顾客付款码扣款。

## 无法启动时

- 提示找不到Python或 `py`：先安装Python 3.12，然后重新双击启动文件。
- 提示找不到Chrome：确认Chrome已安装；也可从终端运行 `py -3.12 run.py --test-mode`，使用系统默认浏览器。
- 端口冲突：关闭之前的测试窗口，或运行 `启动测试版.bat --port 8768`。
- 浏览器没有自动打开：保持服务窗口运行，把它显示的本机地址粘贴进Chrome。
- 提示拒绝已有非测试目录：使用新的空目录。不要给正式账本添加测试标记来绕过检查。
- 金额或类目未填：界面会显示缺少的字段，填写后再保存。
- 保存时网络异常：不要刷新或重新开单，点击“核实上次保存并备份”，沿用原请求核对，避免重复入账。
  该手动记账请求仅在当前弹窗保留；若已经关页，应先在账目列表核查是否保存，不要直接再记一笔。

## 数据隔离

测试模式默认忽略正式数据环境变量，使用 `test-data` 和8767端口；正式模式仍使用 `data` 和8765端口。
也可明确指定新的测试目录：

```powershell
py -3.12 run.py --test-mode --data-dir "D:\餐饮测试账本" --browser chrome
```

测试启动器拒绝未带测试标记的非空目录，初始化在临时目录完成后再整体移入目标位置。
测试数据的备份和原图与正式账本分开；不会连接云端私人账本。
界面的确认收款仅保存测试账目和扣减测试库存，不会向任何人发起扣款。

如需从头再试，先停止测试服务并自行另选一个空目录；本版不提供一键删除账本按钮。
可选OCR需单独安装依赖和模型。若用自选测试目录，安装OCR时传入同一个 `--data-dir`。

## 截图审核与备份恢复

同一张图中的多笔账单可以逐笔修改。保存其中一笔或返回截图列表，不会清空当前标签页里其他笔的修改。
切换收支方向后，原方向的类目、转入账户和分类学习选择会保留；晚返回的分类建议不会覆盖人工刚选的类目。
这些尚未入账的修改仅暂存在当前标签页内存。刷新或关页会提示；若确认离开，尚未入账的修改会丢失。
正式入账后才写入数据库及逐笔备份，其他设备看到的是已确认的数据。

测试版下载的完整备份包含 `.test-ledger.json` 标记。恢复步骤：

1. 退出测试程序，将备份完整解压到一个新目录，例如 `D:\餐饮测试恢复`。不要覆盖原目录，也不要遗漏隐藏标记文件。
2. 在软件目录运行 `启动测试版.bat --data-dir "D:\餐饮测试恢复"`。
3. 登录后确认“模拟账本”标识，以及账目笔数、分类总额、库存和小票。
4. 恢复启动会检查原图哈希并补齐独立副本；一份原图损坏时可从另一份恢复，两份都无效时会报错并要求从其他完整备份恢复。

正常账本的备份不会被添加测试标记。不要手工给正式账本加测试标记来绕过目录保护。
